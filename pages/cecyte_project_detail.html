CECyTE Admin Software

School administration software definido mediante FR/NFR elicitation, stakeholder interviews y relational database design para CECyTE Puebla.

MySQL PHP HTML / CSS MoProSoft Normalización BD Requerimientos
Contexto

¿Qué problema resuelve?

CECyTE Puebla operaba sus procesos de inscripción, control escolar y gestión de planteles de forma manual y fragmentada. El software centraliza la administración de aspirantes, estudiantes, periodos, bajas, revalidaciones y carreras en un sistema relacional normalizado accesible desde cualquier plantel.

cecyte_db.mwb — Modelo Entidad-Relación
Metodología

Proceso de desarrollo

El proyecto siguió un proceso estructurado desde la elicitación de requerimientos hasta la entrega de documentación técnica.

01
Fase 1
Stakeholder Interviews
Entrevistas con personal administrativo de CECyTE para identificar pain points, flujos existentes y necesidades no cubiertas del sistema actual.
02
Fase 2
Elicitación FR / NFR
Definición de requerimientos funcionales y no funcionales usando plantillas estructuradas. Clasificación por módulo: inscripción, control escolar, planteles y reportes.
03
Fase 3
Diseño del modelo relacional
Modelado de 15+ entidades normalizadas a 3FN: Aspirante, Estudiante, Periodo, Plantel, Carrera, Baja, Revalidación, Estado/Municipio y tablas de relación.
04
Fase 4
Documentación MoProSoft
Aplicación del framework MoProSoft + CMMI al proceso de seguimiento académico de internado médico hospitalario. Entrega de Section 4 documentation en inglés.
Especificaciones

Requerimientos del sistema

Requerimientos levantados mediante entrevistas y validados con los stakeholders de CECyTE Puebla.

FR-01El sistema debe permitir registrar aspirantes con datos personales, académicos y de contacto completos.
FR-02El sistema debe gestionar el proceso de inscripción vinculando aspirantes a periodos y planteles específicos.
FR-03El sistema debe registrar y consultar bajas de estudiantes con motivo, fecha y solicitud de certificado.
FR-04El sistema debe administrar revalidaciones académicas con créditos obtenidos y calificaciones de origen.
FR-05El sistema debe gestionar la oferta de carreras por plantel a través de la tabla Carrera_Plantel.
FR-06El sistema debe generar reportes de asistencia y calificaciones por periodo, grupo y materia.
NFR-01Rendimiento: las consultas de listado de estudiantes deben responder en menos de 2 segundos con hasta 5,000 registros.
NFR-02Seguridad: acceso por roles (administrador, docente, control escolar) con sesiones autenticadas.
NFR-03Disponibilidad: el sistema debe operar sin interrupciones durante el horario escolar (7am – 9pm).
NFR-04Usabilidad: la interfaz debe ser operable sin capacitación técnica por personal administrativo no especializado.
NFR-05Mantenibilidad: el código debe seguir convenciones de nomenclatura consistentes y contar con documentación interna.
