# HTML Writing Guide

A structured reference for writing clean, accessible, and maintainable HTML — whether authored by a human or generated by AI.

---

## 1. Document Structure

Every HTML file must begin with a valid document skeleton. Omitting any of these elements causes browsers to enter quirks mode or screen readers to lose context.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="A concise summary of the page content.">
  <title>Page Title — Site Name</title>
  <link rel="stylesheet" href="styles/main.css">
</head>
<body>
  <!-- Page content goes here -->
</body>
</html>
```

### Rules

- **Always** declare `<!DOCTYPE html>` as the very first line.
- Set the `lang` attribute on `<html>` to the primary language of the page (e.g., `en`, `es`, `fr`).
- Include `<meta charset="UTF-8">` **before** the `<title>` tag.
- Include the viewport meta tag for responsive design.
- Provide a meaningful `<title>` that is unique per page.
- Add a `<meta name="description">` with a compelling summary (≤ 160 characters).

## 2. Semantic HTML

Use elements for their **meaning**, not their default appearance. Styling is CSS's job.

### Sectioning Elements

| Element      | Purpose                                                |
| ------------ | ------------------------------------------------------ |
| `<header>`   | Introductory content or navigational aids for a section |
| `<nav>`      | Primary navigation links                               |
| `<main>`     | The dominant, unique content of the page                |
| `<section>`  | A thematic grouping of content with a heading           |
| `<article>`  | Self-contained, independently distributable content     |
| `<aside>`    | Tangentially related content (sidebars, callouts)       |
| `<footer>`   | Closing information for a section or the page           |

### Rules

- Use **one** `<main>` element per page.
- Every `<section>` should have a heading (`<h2>`–`<h6>`).
- Do **not** use `<div>` or `<span>` when a semantic element exists for the purpose.
- Reserve `<div>` for non-semantic grouping needed only for layout or scripting hooks.

### ❌ Bad

```html
<div class="nav">
  <div class="nav-item"><a href="/">Home</a></div>
</div>
```

### ✅ Good

```html
<nav aria-label="Main navigation">
  <ul>
    <li><a href="/">Home</a></li>
  </ul>
</nav>
```

## 3. Heading Hierarchy

Headings create the outline of the document. Assistive technologies rely on them for navigation.

### Rules

- Use **exactly one** `<h1>` per page — it is the page title.
- Never skip heading levels (e.g., jumping from `<h2>` to `<h4>`).
- Do not choose heading levels for font size; use CSS instead.

### ❌ Bad

```html
<h1>Welcome</h1>
<h3>Our Services</h3>   <!-- Skipped h2 -->
<h5>Contact Us</h5>     <!-- Skipped h4 -->
```

### ✅ Good

```html
<h1>Welcome</h1>
<h2>Our Services</h2>
<h3>Web Development</h3>
<h3>Design</h3>
<h2>Contact Us</h2>
```

## 4. Indentation & Formatting

Consistent formatting makes HTML scannable at a glance.

### Rules

- Use **2 spaces** for indentation (no tabs).
- Indent every child element one level deeper than its parent.
- Place block-level elements on their own line.
- Inline elements (`<a>`, `<strong>`, `<em>`, `<span>`, `<code>`) may remain on the same line as their surrounding text.
- Keep lines under **120 characters** when possible.
- Use blank lines to separate major sections (`<header>`, `<main>`, `<footer>`, etc.).

### Example

```html
<main>
  <section id="about">
    <h2>About Us</h2>
    <p>
      We are a team of <strong>passionate developers</strong> building
      tools for the modern web.
    </p>
  </section>

  <section id="projects">
    <h2>Projects</h2>
    <ul>
      <li><a href="/project-alpha">Project Alpha</a></li>
      <li><a href="/project-beta">Project Beta</a></li>
    </ul>
  </section>
</main>
```

## 5. Attributes

### Rules

- Always use **double quotes** for attribute values: `class="hero"`.
- Write attributes in **lowercase**.
- Use the following recommended attribute order for readability:
  1. `id`
  2. `class`
  3. `name` / `type` / `for`
  4. `src` / `href` / `action`
  5. `alt` / `title` / `aria-*` / `role`
  6. `data-*`
  7. Boolean attributes (`disabled`, `required`, `checked`)
- Boolean attributes do **not** need a value — their presence is sufficient.
- Remove redundant attributes (e.g., `type="text/javascript"` on `<script>`, `type="text/css"` on `<style>`).

### Example

```html
<input
  id="email"
  class="form-input"
  type="email"
  name="user_email"
  placeholder="you@example.com"
  aria-describedby="email-help"
  required
>
```

## 6. Naming Conventions

### IDs

- Use `kebab-case`: `id="hero-section"`.
- IDs must be **unique** within a page.
- Use IDs for anchor targets, label associations, and JavaScript hooks — not for styling.

### Classes

- Use `kebab-case`: `class="card-header"`.
- Prefer semantic, descriptive names over presentational ones.
- Consider a methodology like **BEM** for larger projects.

| ❌ Avoid             | ✅ Prefer               |
| -------------------- | ----------------------- |
| `class="red-text"`   | `class="error-message"` |
| `class="big-box"`    | `class="feature-card"`  |
| `class="left-float"` | `class="sidebar"`       |

## 7. Images & Media

### Rules

- **Always** provide an `alt` attribute on `<img>`.
  - Descriptive `alt` for informational images: `alt="Team brainstorming at a whiteboard"`.
  - Empty `alt=""` for purely decorative images (so screen readers skip them).
- Use modern formats (`WebP`, `AVIF`) with `<picture>` fallbacks when possible.
- Specify `width` and `height` attributes to prevent layout shifts.
- Lazy-load off-screen images with `loading="lazy"`.

### Example

```html
<figure>
  <picture>
    <source srcset="images/hero.avif" type="image/avif">
    <source srcset="images/hero.webp" type="image/webp">
    <img
      src="images/hero.jpg"
      alt="Sunset over the mountains"
      width="1200"
      height="630"
      loading="lazy"
    >
  </picture>
  <figcaption>Sunset over the Sierra Nevada, 2025.</figcaption>
</figure>
```

## 8. Links

### Rules

- Use descriptive link text that makes sense out of context.
- Add `rel="noopener noreferrer"` to links with `target="_blank"`.
- Do **not** use `javascript:` in `href`.

| ❌ Avoid                                      | ✅ Prefer                                      |
| --------------------------------------------- | ---------------------------------------------- |
| `<a href="#">Click here</a>`                  | `<a href="/pricing">View pricing plans</a>`    |
| `<a href="https://..." target="_blank">Link</a>` | `<a href="https://..." target="_blank" rel="noopener noreferrer">Visit docs</a>` |

## 9. Forms

### Rules

- Every input must have an associated `<label>` using `for`/`id` pairing.
- Group related fields with `<fieldset>` and `<legend>`.
- Use the most specific `type` attribute (`email`, `tel`, `url`, `number`, `date`, etc.).
- Provide clear error messages associated with their input via `aria-describedby`.
- Include a visible submit button (not just Enter-key submission).

### Example

```html
<form action="/subscribe" method="post">
  <fieldset>
    <legend>Newsletter Signup</legend>

    <label for="full-name">Full Name</label>
    <input id="full-name" type="text" name="full_name" autocomplete="name" required>

    <label for="email-address">Email Address</label>
    <input
      id="email-address"
      type="email"
      name="email"
      autocomplete="email"
      aria-describedby="email-hint"
      required
    >
    <small id="email-hint">We'll never share your email.</small>

    <button type="submit">Subscribe</button>
  </fieldset>
</form>
```

## 10. Accessibility (a11y)

### Rules

- Use **semantic elements** first — they carry built-in roles and keyboard behavior.
- Add `aria-label` or `aria-labelledby` to interactive elements that lack visible text.
- Ensure all interactive elements are reachable via **keyboard** (`Tab`, `Enter`, `Space`).
- Do **not** use `tabindex` values greater than `0`; they break the natural tab order.
- Provide `skip-to-content` links for keyboard users.
- Maintain a **minimum contrast ratio** of 4.5:1 for normal text (WCAG AA).

### Skip-to-Content Example

```html
<body>
  <a href="#main-content" class="skip-link">Skip to main content</a>

  <header><!-- navigation --></header>

  <main id="main-content">
    <!-- primary content -->
  </main>
</body>
```

```css
.skip-link {
  position: absolute;
  left: -9999px;
}
.skip-link:focus {
  left: 16px;
  top: 16px;
  z-index: 1000;
}
```

## 11. Scripts & Stylesheets

### Rules

- Place `<link>` stylesheet references in the `<head>`.
- Place `<script>` tags at the **end of `<body>`**, or use `defer` / `module` in the `<head>`.
- Prefer external files over inline `<style>` and `<script>` blocks.
- Use `type="module"` for ES module scripts.

### Example

```html
<head>
  <link rel="stylesheet" href="styles/tokens.css">
  <link rel="stylesheet" href="styles/base.css">
  <link rel="stylesheet" href="styles/components.css">
  <script type="module" src="lib/main.js" defer></script>
</head>
```

> **Note:** `defer` is technically redundant on `type="module"` scripts (modules are deferred by default), but including it communicates intent clearly.

## 12. Comments

### Rules

- Use comments to explain **why**, not **what**.
- Mark major page sections with comment banners for easy scanning.
- Remove commented-out code before committing to production.

### Example

```html
<!-- ======================== -->
<!-- HERO SECTION             -->
<!-- ======================== -->
<section id="hero" class="hero">
  <!-- Background handled via CSS to support reduced-motion preference -->
  <h1>Build Something Great</h1>
  <p>Modern tools for modern creators.</p>
</section>
```

## 13. Tables

Use `<table>` **only** for tabular data, never for layout.

### Rules

- Always include `<thead>`, `<tbody>`, and optionally `<tfoot>`.
- Use `<th>` with a `scope` attribute (`col` or `row`) for header cells.
- Add a `<caption>` to describe the table's purpose.

### Example

```html
<table>
  <caption>Q1 2026 Revenue by Region</caption>
  <thead>
    <tr>
      <th scope="col">Region</th>
      <th scope="col">Revenue</th>
      <th scope="col">Growth</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">North America</th>
      <td>$1.2M</td>
      <td>+12%</td>
    </tr>
    <tr>
      <th scope="row">Europe</th>
      <td>$860K</td>
      <td>+8%</td>
    </tr>
  </tbody>
</table>
```

## 14. Common Anti-Patterns

Avoid these frequent mistakes:

| Anti-Pattern | Why It's Wrong | Correct Approach |
|---|---|---|
| Using `<br>` for spacing | Line breaks are not layout tools | Use CSS `margin` or `padding` |
| Using `<b>` / `<i>` for emphasis | They carry no semantic meaning | Use `<strong>` / `<em>` |
| Nesting `<a>` inside `<a>` | Invalid HTML; undefined behavior | Restructure so links don't nest |
| Using `<div>` for clickable areas | `<div>` is not interactive by default | Use `<button>` or `<a>` |
| Inline styles everywhere | Hard to maintain, overrides cascade | Use external stylesheets |
| Missing `alt` on images | Inaccessible to screen readers | Always provide `alt` text |
| Using `onclick` attributes | Mixes behavior with structure | Use `addEventListener` in JS |

## 15. Validation Checklist

Before shipping any page, verify:

- [ ] The document passes the [W3C Markup Validator](https://validator.w3.org/).
- [ ] There is exactly one `<h1>` and headings follow a logical hierarchy.
- [ ] All images have appropriate `alt` attributes.
- [ ] All form inputs have associated `<label>` elements.
- [ ] Interactive elements are keyboard-accessible.
- [ ] The page is usable with CSS disabled (content order makes sense).
- [ ] No inline styles are used (unless dynamically set by JS for a specific reason).
- [ ] External links with `target="_blank"` include `rel="noopener noreferrer"`.
- [ ] The `<title>` and `<meta description>` are present and descriptive.
- [ ] The page passes a basic [Lighthouse](https://developer.chrome.com/docs/lighthouse/) accessibility audit with a score ≥ 90.

## 16. Quick Reference — Self-Closing Elements

In HTML5, the following elements are **void** (self-closing) and must **not** have a closing tag:

```
<area>  <base>  <br>  <col>  <embed>  <hr>  <img>
<input>  <link>  <meta>  <source>  <track>  <wbr>
```

The trailing slash (`<br />`) is optional in HTML5 but required in XHTML. Pick one convention and be consistent across the project.
